# AI 起草稿的返修流程

先分清两件事：

- **科学层**：数据、统计、结论。AI 不能替你负责，语言工具也不能补救。
- **语言层**：主张强度、引文绑定、段落组织、句法注册。这一层可以做到与顶刊同带。

多项盲评研究显示，审稿人识别 AI 摘要的准确率接近随机；有的研究里，经 AI 润色的摘要被评为更清晰。这说明**语言层不是主要破绽**，也说明**不能靠语言层判断合规**。期刊要求披露，披露与否和语言好坏是两件事。

## 第 0 步：先做主张清单

不要先改句子。先把全文的主张抽出来，逐条填表：

| # | 主张（原句） | 层级 | 证据 | 状态 |
|---|---|---|---|---|
| 1 | Canopy cover is the dominant driver. | 因果/机制 | 无 | 缺 |
| 2 | Each 10% increase lowered temperature by 1.8 °C. | 方向 | 模型 + 数据 | 有 |
| 3 | Dense neighbourhoods benefit most. | 相关 | 数据 | 有 |

层级按 `docs/02-组织方式.md` 的阶梯：观察 / 相关 / 方向 / 机制 / 因果。

状态只有三种：有证据、可降级、必须补。**没有第四种叫「写得像有证据」。**

## 第 1 步：降级或补证

- 有数据但设计不支持因果 → 降到「相关」或「方向」：`causes` → `is associated with` / `lowered`。
- 有引文但引文不支持本句 → 换引文，或降级。
- 什么都没有 → 删掉，或明确标成假设：`we speculate that`。

这一步不改语言风格，只改强度。做完之后，`strong_claim_unsupported_per_k` 应该接近 0。

## 第 2 步：引文绑定

顶刊 84% 的引文落在句末。做法：

1. 找到每个引文现在支撑的是哪半句。
2. 把被支撑的主张移到句末。
3. 引文紧跟其后。
4. 一句里多条引文支撑不同主张时，拆成两句。

> ❌ A growing body of literature [1] has examined vegetation, yet mechanisms [2] remain unclear.
> ✅ Most evidence comes from megacities [3]. Whether it generalises to medium-sized cities is unclear, because coarse products resolve thermal gradients poorly [4].

## 第 3 步：段落手术

- 一段一个主张。第二、第三个主张拆出去。
- 段首句给结论，后面给证据，段末回扣或引文收束。
- Results 段不解释机制；解释移到 Discussion。
- 段均 107–138 词。超过 150 词先怀疑，不要先润色。

## 第 4 步：句子注册

- 目标：平均 23–25 词，超长句 ≤20%。
- 一个从句一个逻辑关系。两个以上，拆。
- 名词化链条改动词：`implementation of an assessment` → `we assessed`。
- 删句首连接词：`However,` / `Moreover,` / `Furthermore,`。靠语序推进。
- 补回 `we`：顶刊第一人称 3.3–7.8/千词。把施动者全删掉不是客观，是含糊。
- 被动留给 Methods。Results 与 Discussion 优先主动。

## 第 5 步：摘要四步

按 `docs/02-组织方式.md` 的模板压缩到 187–238 词：

1. 背景与缺口：一句。
2. 做法：一句，写清设计和数据。
3. 结果：三到四句，每句一个数字或方向。
4. 意义：一句，带边界。

AI 稿常见的 300 词摘要，删掉前 100 词背景，通常就进带了。

## 第 6 步：跑检查器，然后停手

```bash
paper-voice manuscript.md --md report.md
paper-voice --compare before.md after.md
```

判读顺序：

1. **P0 清零。** 无支撑强断言、句末引文占比。这两项不过，其他都不用看。
2. **P1 看方向。** 摘要词数、强断言、引文密度、套词。
3. **P2 只修有明确病灶的项。** 句长、段落、名词化、被动。
4. **P3 不追。** 句长 CV、段长 CV 在短文本上波动大，报告会提示样本量。

**A/B 级问题清零就停。** 不要为了把每个指标推到带中心继续改。这是这类工具最常见的破坏：改到第三轮，文章变成短句电报体。

## AI 起草稿的十个高频病灶

| 病灶 | 表现 | 改法 |
|---|---|---|
| 主张跳级 | `demonstrate` / `prove` 后面没有证据 | 降级或补证 |
| 引文句首堆叠 | `[1] showed ... [2] argued ...` | 主张在前，引文在后 |
| 摘要过长 | 280–320 词，背景占一半 | 压到 220 词，四步 |
| Results 解释机制 | 结果段出现 `because` / `suggesting` | 移到 Discussion |
| Discussion 复述结果 | 第一段又讲一遍数字 | 第一段直接回答问题 |
| 连接词串场 | 每段 `However` / `Moreover` | 删，靠语序 |
| 名词化链条 | `the implementation of the assessment of` | 改动词 |
| 套词密度高 | `delve` / `underscore` / `pivotal` | 换成具体动作 |
| 时态混乱 | Results 用现在时，Discussion 用过去时 | Results 过去，解释现在 |
| 过度被动 | Results 里全是 `was observed` | 改 `we observed` |

## 不要做的五件事

1. **不要补数据。** 编一个数字，整篇可信度归零。
2. **不要升级主张。** 语言不能比设计高一级。
3. **不要为了分位数改句子。** 机械对齐比不改更糟。
4. **不要加「人味」。** 口语、错别字、第一人称乱入，不解决语言层问题。
5. **不要隐藏 AI 使用。** 披露写在 Methods，语言好坏与披露是两件事。

## 披露

见 `docs/00-政策.md`。一句话版本：AI 可以润色，不能署名；实质性使用要写清模型与用途；作者对全部内容负责。

## 一句实话

语言层能过审，科学层不能替。审稿人可能看不出文本是 AI 起草的，但一定看得出主张没有证据。
