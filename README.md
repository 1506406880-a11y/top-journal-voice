# paper-voice · 顶刊语体体检

**不看词表，把稿子放进 49 篇开放获取 Nature 论文的分位带。**

一个零依赖的 Python 工具，加一份可复算的语体基准。它检查的不是「像不像 AI」，而是四件审稿人真正会卡的事：主张有没有证据、引文有没有绑定、段落有没有单一主张、摘要有没有在前三十秒给出结果。

```bash
paper-voice 稿件.md
```

---

## 三个读数

从 Europe PMC 取 49 篇 2018–2025 年的开放获取 Nature 论文，逐篇计算后取跨篇分位：

| 指标 | P25 | P50 | P75 |
|---|---|---|---|
| 平均句长（词） | 22.8 | 24.2 | 25.2 |
| 句末引文占比 | 78% | 84% | 89% |
| 无支撑强断言（/千词） | 0.00 | 0.13 | 0.24 |
| 摘要词数 | 187 | 222 | 238 |
| 引文密度（/千词） | 16.4 | 20.7 | 24.8 |
| 对冲词（/千词） | 1.83 | 2.98 | 4.31 |
| 强断言（/千词） | 0.30 | 0.50 | 0.81 |
| 连接词（/千词） | 1.73 | 2.39 | 3.20 |

三个结论：

**一、引文跟着主张走。** 84% 的引文落在句末，不是句首堆一串。句首引文通常只用于承接前文。

**二、无支撑强断言几乎为零。** `demonstrate` / `prove` / `establish` / `clearly` 加上「无引文、无数据」的组合，P75 只有 0.24 次/千词。这是审稿意见里最常见的靶子。

**三、顶刊句子比想象中短。** 中位 24 词，超长句（>35 词）只占 16%。AI 起草稿常在 30 词以上。

---

## 它做什么

给定一篇英文或中文稿件，输出：

- **P0 主张与证据**：无支撑强断言、句末引文占比。
- **P1 摘要与断言强度**：摘要词数、强断言、对冲、引文密度、学术套词。
- **P2 句子与段落**：句长、超长句、段均词数、名词化、被动、第一人称、连接词。
- **P3 节奏与结构**：句长 CV、段长 CV、题名、结构缺项。

每条都带：读数、顶刊分位带、方向、具体改法。报告按 P0→P3 排修改顺序。

## 它不做什么

- 不判断作者身份，不输出 AI 概率。
- 不检查数据、统计、伦理审批、利益冲突。
- 不补数据、不补引文、不编细节。
- 不承诺录用。语言过关不等于科学过关。
- 不帮隐藏 AI 使用。披露是另一件事，见 [`docs/00-政策.md`](docs/00-政策.md)。

## 安装

Python 3.8+，无第三方依赖。

```bash
git clone https://github.com/1506406880-a11y/top-journal-voice.git
cd top-journal-voice
pip install -e .
```

不安装也可以：

```bash
python -m paper_voice.cli 稿件.md
```

自检：

```bash
python -m paper_voice.cli --selftest
python -m unittest discover -s tests -t .
```

## 用法

```bash
# Markdown 报告
paper-voice manuscript.md

# 写到文件
paper-voice manuscript.md --md report.md

# 机器可读
paper-voice manuscript.md --json > report.json

# 改写前后对比
paper-voice --compare before.md after.md

# 列出可用基准
paper-voice --list-profiles

# CI：P0 越界就失败
paper-voice manuscript.md --fail-on p0
```

中文稿自动切到 `cn-t1` 基准；也可以 `--profile cn-t1` 强制指定。

### 作为 Agent Skill

把 `SKILL.md` 复制到 agent 的 skills 目录，或用支持 Agent Skills 的安装器：

```bash
npx skills add https://github.com/1506406880-a11y/top-journal-voice
```

Skill 的工作流是：体检 → 只读 P0 → 主张清单 → 降级或补证 → 引文绑定 → 段落与句子 → 摘要 → 复测停手。

## 示例

`examples/` 里有一篇刻意写成 AI 腔的合成稿和它的返修版：

| 指标 | 改前 | 改后 | 顶刊带 |
|---|---|---|---|
| 无支撑强断言 | 2.97 | **0** | 0–0.24 |
| 句末引文占比 | 33% | **88%** | 78–89% |
| 强断言密度 | 5.94 | 0 | 0.30–0.81 |
| 学术套词密度 | 13.4 | 0 | 0.12–0.75 |
| 引文密度 | 5.94 | **17.9** | 16.4–24.8 |
| 摘要词数 | 279 | 175（临界） | 187–238 |
| 摘要平均句长 | 69.8 | 22.0（临界） | 22.8–28 |
| 平均句长 | 30.6 | 21.5（偏低） | 22.8–25.1 |
| 名词化密度 | 58.0 | **42.9** | 37.6–43.4 |
| 连接词密度 | 11.9 | **1.79** | 1.73–3.20 |

## 语体基准确怎么用

分位带不是分数线。它的作用是排序：先修 P0，再看 P1，P2 只修有明确病灶的，P3 不追。

短文本（<1500 词）的密度类指标会被放大：一个 `establish` 在 500 词里就是 2 次/千词。报告会提示这一点。**不要为了把指标推到带中心改文章。**

## 中文基准

`cn-t1` 来自 30 篇中文 T1 期刊论文的实测：平均句长 46.9–62.0 字，句长 CV 0.54–0.65，段均 210–314 字，段末引文收束 10.5–27.5%。口径与英文不同：中文的「段末引文收束」指段落最后是引文，不是句末。

## 复算语料

```bash
python scripts/build_corpus.py --per-year 14 --from-year 2018 --to-year 2025
```

脚本从 Europe PMC 取开放获取全文，只保存聚合分位数，不保存、不再分发论文全文。本地 `_cache/` 是 XML 缓存，已在 `.gitignore` 里。

## 局限

- 只覆盖 Nature，不含 Science、Cell、Nature 子刊；跨刊使用要重算。
- 只覆盖开放获取全文，样本偏向近年、生命科学与物质科学。
- 按引用取样的语体可能比普通刊文更「标准」。
- 分节指标（如 Discussion 对冲密度）样本更少，只作参考。
- 所有数字是 2026-10 的观测；编辑规范与模型都在变。
- 语言层不能替代科学层。审稿人可能看不出文本是 AI 起草的，但一定看得出主张没有证据。
